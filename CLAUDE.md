# MOI "The Promise of Safety" - read this first

Unity 6000.1.4f1 project (URP, OpenXR + VIVE OpenXR 2.5.1) for a museum VR kiosk: UAE Ministry of Interior, agency
Al Fakhr, built by GameX (the user's studio). Headset: **VIVE Focus Vision** (standalone Android, package
`com.gamex.moi.promiseofsafety`). Since 2026-09-29 the START screen is a looping 8K 360 video
(`Al_Fakhr_Intro_360.mp4`, 8.2 s, bundled as `Assets/StreamingAssets/StartScreen360.mp4`, with its sound). The video
draws its own START panel straight ahead (yaw 0, pitch +1.85 deg, 25 x 9.7 deg); our START button is an INVISIBLE
hotspot over it (`ExperienceSequence.startHotspot`: 27 x 11 deg, 8 m in front of the head, follows the head position;
started by controller only - laser + trigger, or A/X; looking at it does nothing: `ExperienceHud.gazeStart` = false). Museum room, crystal, title all off; the title only returns to say the film
is missing. START plays one 8K 360-degree film (`Al_Fakhr_Final_Version_360.mp4`, 7680x3840 8-bit HEVC, 140 s, copied
to the device as `journey.mp4`), then returns to the START screen. During the film the picture ZOOMS OUT (user: "like
zooming out in VLC, the video seen from a little farther") 1 -> 0.8 (= 1.25 times farther), eased over 35-36 s, held
to the end; every start begins at 1: `ExperienceSequence.filmZoom`, overridable per film in `film.json` (`zoomAt`,
`zoomOver`, `zoomTo`; `"zoomTo": 1` = off, below 1 = out, above 1 = in). The sky shader `MOI/Panorama360` =
Skybox/Panoramic + `_Zoom` (front scaled, easing back to 1 behind: angle t shows the picture from
t - (1 - 1/zoom) sin t, valid for zoom > 0.5). Everything around it (button, intro, mirror screen) is a PowerShell
"station"; the button box's texts are in `Deploy/button-commands.txt` (`command = PUSH_TO_PLAY, START`, `port = auto`, `baud = 9600` - nothing else, user's wish).

Full history and every decision: `Deploy/dev-notes/moi-vr-project-log.md` (dated log, long) and
`Deploy/DEPLOYMENT.md` (the technical guide). Older notes: `Assets/MOI/README.md`, `ContentServer/README.md`.
`HANDOFF.md` in this folder is from 2026-09-25 and OUTDATED.

## The two deliverables (both built by us, both must keep working)
1. **MOI_VR_Station** - the app runs ON the headset (APK). The PC shows "Press the button" / intro / a scrcpy mirror
   of the headset. Installed with `SETUP.bat`. Package: `Delivery/MOI_VR_Station(.zip)`.
2. **MOI_PC_Demo** - a Windows build of the app runs on an RTX 5080 PC and is streamed to the headset over USB
   (VIVE Hub / VIVE Business Streaming + SteamVR as the OpenXR runtime). The app's own window is the PC mirror.
   Package: `Delivery/MOI_PC_Demo(.zip)`; sources `Deploy/pc-demo/`. The user tests this on the ASUS PC.

Station flow (`Deploy/visitor-station.ps1`, WPF, states Waiting -> Intro -> Wear -> Mirror -> Waiting):
button (Arduino on USB serial, or F9) -> intro video -> "put on the headset" -> mirror -> START in headset -> film
-> back to "Press the button". Default rules: headset put on at ANY time -> mirror at once; headset off 5 s ->
back to Waiting and the app is told to reset (`command.txt`). This is the flow the user wants (confirmed 2026-09-29,
incl. "headset on during the intro -> intro stops, view shows"); the PC demo has ONE start file, `START PC DEMO.bat`.
`-WaitForButton` still exists in the station as an advanced option only.

## Setting up on a new PC (e.g. the ASUS / RTX 5080)
- Two copies (2026-09-29): development continues on the Lenovo laptop, project now at `D:\VR` (moved from
  `C:\Users\Lenovo\VR`, which is gone; desktop icons "Start/Stop VR Station" point to `D:\VR\Deploy`); the ASUS PC (RTX 5080, the
  PC-demo test machine) has a copy at `C:\Users\ASUS\Desktop\VR\VR` (the inner `VR`, made from `VR.rar` at 12:02, so it
  lacks later changes). Open the folder that contains `Assets` in Unity Hub and in Claude Code.
- Unity Hub + editor **6000.1.4f1 exactly**, with Android Build Support (SDK/NDK/OpenJDK) and Windows Build Support (Mono).
  Sign in to Unity. First open re-imports everything (long). Do not let Unity upgrade the project.
- **`Packages/com.htc.upm.vive.openxr` must stay embedded with its real binaries** (as a git dependency the .aar/.so are
  135-byte LFS pointers and the APK build fails with "openxr_loader.aar: zip END header not found").
- APK signing uses the machine's default debug keystore (`%USERPROFILE%\.android\debug.keystore`). An APK built with a
  different keystore will NOT install over one already on a headset (SETUP offers uninstall; or copy the old laptop's
  `debug.keystore`). The headsets also trust the old laptop's adb key - expect the "Allow USB debugging" prompt once.
- Tools: ffmpeg (was TouchDesigner's `C:\Program Files\Derivative\TouchDesigner\bin\ffmpeg.exe`: hevc_qsv, no libx265),
  Python 3 (for `Deploy/dev-tools/compilecheck.py`), scrcpy is bundled in the station package.
- The film is NOT in the project. Master: `AlFakher_New.mp4` (also inside both zips as `content\journey.mp4`).

## Build / verify
- Windows build (batch, editor closed): `Unity.exe -batchmode -quit -projectPath <proj> -buildTarget Win64
  -executeMethod MOI.EditorTools.MoiBuild.BuildWindows -logFile <log>` -> `Builds/Windows/MOI_PromiseOfSafety.exe`; then run
  Unity once more with `-buildTarget Android` to switch the project back. APK: same with `-buildTarget Android` and
  `MOI.EditorTools.MoiBuild.BuildApk` -> `Builds/MOI_PromiseOfSafety.apk`. Windows is forced to DX11 (DX12 made video
  decode fall back to the CPU).
- With the editor open, batchmode is blocked by the project lock; use the command file described in
  `Deploy/dev-notes/unity-editor-remote-control.md` (`Temp/moi-command.txt`: configure, build-scene, build-apk,
  build-windows, capture-stills).
- Offline C# check: `python Deploy/dev-tools/compilecheck.py` - Runtime part must be "clean"; the Editor part prints
  known false `CS0012 mscorlib` errors.
- Station tests: `Deploy/dev-tools/wear_scenarios.ps1` (simulated headset, ~4 minutes, takes over the screen - never run
  while the user works on that PC), `pc_*`/`headset_*` need a real headset.
- Packages: zips must be built with `System.IO.Compression.ZipArchive` and FORWARD-slash entry names (PS 5.1
  `Compress-Archive` / `CreateFromDirectory` write backslashes); exclude `logs` and `intro_previous.mp4`. Package folder
  contents: see the current `Delivery/MOI_VR_Station` and `Delivery/MOI_PC_Demo/MOI_PC_Demo`. Master copies of the
  station scripts live in `Deploy/`; copy `visitor-station.ps1` and `button-commands.txt` into both packages after every change.

## Rules learned the hard way
- `visitor-station.ps1`: PowerShell variables are case-insensitive - NEVER name a handler parameter `$s` (it hides the
  station state `$S`; it broke closing and the intro). Use `$src`. `powershell -File` silently ignores unknown
  parameters. Verify syntax in PowerShell, not with the Bash tool's parser.
- WPF `MediaElement` freezes on the first play of a freshly opened video: the intro is kept loaded and warmed up under
  an opaque cover. Don't "simplify" that.
- Windows/headset players can't play 10-bit HEVC (freezes at 0 fps). Films must be 8-bit HEVC (or H.264).
- The app writes `status.txt` (`state= worn= paused= films=`); the station only trusts it while the app runs. On Windows
  the wear sensor is `OpenXRUtility.IsUserPresent`, polled each frame (events alone miss a headset already worn at start).
  PC demo: the station also reads SteamVR's state from `<Steam>\logs\vrmonitor.txt` (Ready / Standby) as a second signal
  (`Read-SteamVrState`; rules in DEPLOYMENT.md; unit test `Deploy/dev-tools/steamvr_signal_test.ps1`).
- adb: starting the adb server can take over 5 s (5.1 s on the laptop); the station's headset reader used to cut every adb
  call at 5 s, so with no server running it never saw the headset. Fixed 2026-09-29 (`MoiHeadsetPoller`: `start-server`
  with a 30 s limit first and after any cut-off call) - in `Deploy/` only, the packages still have the old copy.
  Several adb versions live on this laptop (VIVE Hub 30.0.4, Unity 34.0.5, scrcpy 37.0.0); all speak protocol 41.
- The laptop (Intel Iris Xe) cannot stream the Windows app to the headset: VIVE's encoder refuses non-Arc Intel GPUs
  (VIVE Hub error 330, `fVSyncCount:0` in `C:\ProgramData\HTC\ViveSoftware\ViveRR\Log`). Tracking and the wear sensor
  still reach SteamVR. Test the PC demo on the ASUS; test the headset build (APK + station) on the laptop.
- `-Windowed` = small test window, not on top (so the chat stays visible on the laptop's single screen); normal start is
  full screen and always on top.
- The Windows build's `.exe` keeps an old date between builds; the real build time is on
  `MOI_PromiseOfSafety_Data\Managed\Assembly-CSharp.dll`.
- Kiosk mode on the headset blocks the VIVE Streaming app; must be off (or allow it) for the PC demo. Exit kiosk: hold
  headset button > Power menu > Quit Kiosk mode > passcode.
- The Arduino button box (Mega 2560, sends `PUSH_TO_PLAY`) runs someone else's firmware - never overwrite it. Its board
  ...510103C0 drops off USB (hardware/cable); F9 is the backup. A spare Mega has no firmware.
- A copied or restored `Library` can be half-broken: the editor then throws on every Scene-view redraw ("Cannot load.
  Path Packages/com.unity.render-pipelines.universal/... AssetDatabase cannot load now", NullReferenceException in
  `StencilCrossFadeRenderPass`, "Blitter is already initialized"). Fix (2026-09-29 on the laptop): close Unity, rename
  `Library` (e.g. `Library.broken-<date>`), reopen with `-buildTarget Android` so it is rebuilt; the source files are fine.
- Safety hook here blocks commands that combine robocopy `/E`/`/MIR` with `Remove-Item`: keep deletes in separate
  calls, never `/MIR`.
- Don't use the user's personal screen recordings from Videos/Downloads as content.
